# Auditoría de componentes UI MobOS — issue #538

Fecha de relevamiento: 2026-10-17. Fase 1: inventario y diagnóstico; no se modificó código de producto.

## Alcance y método

Se revisaron `src/components/ui/`, `src/components/shared/`, `src/components/`, `src/pages/`, `src/index.css`, `tailwind.config.js`, `docs/CAMPOS.md` y `docs/PLANTILLA-OBJETOS.md`. Las ubicaciones y consumidores de esta auditoría se comprobaron con búsquedas de imports/usos del árbol actual. Los conteos de búsqueda son una señal de alcance, no una afirmación de que cada coincidencia sea un duplicado: JSX también usa elementos HTML para estructura, navegación y controles especializados.

El árbol contiene 352 archivos JS/JSX bajo `src/components`, más de 60 objetos en `src/components/shared/` y el punto de entrada `src/components/ui/index.jsx`. `src/index.css` importa los estilos de `owncoding-ui`; `tailwind.config.js` consume su preset y agrega el tema MobOS. Hay 216 archivos de componentes/páginas con un `<Button>` o `<button>`; 131 con campos/selectores; 70 con un diálogo compartido o `role="dialog"`. Son conteos de archivos con al menos una coincidencia.

## Contratos y hallazgos que afectan la auditoría

1. **La documentación contradice el código sobre la propiedad de Modal/Drawer.** `src/components/ui/index.jsx` reexporta ambos desde `owncoding-ui` y comenta que se adoptaron en #323. `docs/CAMPOS.md` §1 y `docs/PLANTILLA-OBJETOS.md` todavía los enumeran como locales. Actualizar estas referencias en una fase documental separada antes de usarla como guía de migración.
2. **Hay controles genéricos y wrappers de dominio coexistiendo.** `ComboBuscador` y `SelectorMedioPago` tienen listas/popup propios; los comboboxes de producto, banco, proveedor y cliente añaden reglas de catálogo. La convergencia debe ocurrir mediante una API genérica y wrappers, manteniendo filtros/datos/creación en el dominio.
3. **El kit está parcialmente externalizado.** `owncoding-ui` está fijado por `package.json`/`package-lock.json` en `v0.68.13`; MobOS reexporta parte del kit, pero mantiene `Card`, `MoneyInput` y `Stat` locales. `MoneyInput` tiene contrato financiero propio (moneda, límites bigint y formato) y no se sustituye sin comparar sus límites con backend/schema.
4. **El inventario actual ya documenta muchas reglas de campos.** `docs/CAMPOS.md` y `docs/PLANTILLA-OBJETOS.md` describen RUC, email, teléfono, dinero, fechas, tamaños y usos. La migración debe tratarlos como contratos a verificar con `backend/prisma/schema.prisma`, validadores y APIs, no como permiso para redefinirlos.
5. **Separación UI/negocio observada:** RUC consulta mediante `shared/rucLookup.js`/API; empresa/cliente/producto/proveedor se resuelven por wrappers y consumidores; dinero delega normalización/límites a `src/utils/moneda.js`; estados leen mapas de `src/lib/estados*.js`. Mantener consultas, permisos, límites comerciales y escritura fuera del componente visual.

## Plan de migración y riesgos

1. Corregir las referencias documentales desactualizadas y registrar la API exacta de la versión fijada de `owncoding-ui`.
2. Crear mapa detallado de consumidores por familia a partir del inventario; empezar con acciones y campos de formularios, donde la reexportación ya ofrece una ruta común.
3. Probar comportamiento del primitivo de dropdown contra `ComboBuscador`, `SelectorMedioPago` y selectores de dominio antes de diseñar una base compartida.
4. Migrar familias en lotes pequeños; preservar `data-testid`, props, valores enviados, formatos y reglas comerciales. No hacer cambios de schema/API desde el componente UI.
5. Consolidar tokens después de un mapa de valores y medición visual en claro/oscuro, escritorio/móvil y pantallas de POS/impresión.
6. Crear catálogo visual local luego de la consolidación. Revisar/publicar en OwnCoding UI únicamente después de que la API local y sus consumidores estén estables.

Riesgos críticos: cambio global de altura/espaciado rompe formularios táctiles; remapeo monetario altera valores o topes; combobox unificado pierde selección/teclado/creación rápida; migrar diálogos rompe foco, dirty state o la hoja móvil; reescribir tablas afecta paginación/acciones/scroll; token de marca cambia contraste y recibos. No se ejecutaron pruebas de comportamiento ni visuales porque esta entrega es un inventario documental y no cambia el producto.

## Novedades para el dueño

- Encontré que MobOS ya tiene una biblioteca compartida grande y que varias pantallas la usan.
- Detecté que la documentación todavía describe `Modal` y `Drawer` como locales aunque ahora vienen de la biblioteca compartida.
- Separé controles realmente distintos (por ejemplo, persona, banco, búsqueda de producto y estados de negocio) de los lugares que conviene evaluar para reducir duplicación.
- Dejé un orden de migración que protege formularios, importes, permisos y pantallas táctiles.
